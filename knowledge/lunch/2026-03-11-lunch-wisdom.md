# 점심 지식 Deep Dive: Notion 디자인 팀의 AI 프로토타이핑 혁명

**출처:** Lenny's Newsletter - "I haven't written a single line of front-end code in 3 months": How Notion's design team uses Claude Code to prototype  
**날짜:** 2026-03-11  
**주제:** AI 기반 디자인 워크플로우, Claude Code 실전 활용

---

## The Big Idea

> "3개월 동안 프론트엔드 코드를 한 줄도 직접 작성하지 않았습니다."

Notion AI 디자이너 Brian Lovin은 Claude Code를 활용하여 디자인 팀의 프로토타이핑 방식을 근본적으로 바꿨습니다. 그는 공유 Next.js 앱을 구축하여 팀 전체가 코드 기반 프로토타입을 협업하고 반복할 수 있는 "프로토타입 플레이그라운드"를 만들었습니다. 이를 통해 **디자인 → 코드 → 테스트** 사이클을 극적으로 단축하고, 특히 AI 제품처럼 동적 상호작용이 중요한 경우 Figma 같은 정적 도구의 한계를 극복했습니다.

---

## Argument Breakdown: 왜 이 방식이 혁명적인가?

### 1. 정적 도구의 한계: AI 제품은 Figma로 디자인할 수 없다

**문제:**
- Figma는 정적 화면을 그리기엔 훌륭하지만, **AI가 실시간으로 응답하는 동적 UX**를 표현하기엔 한계가 명확합니다.
- 예: 채팅 응답 속도, 로딩 상태, 에러 핸들링, 스트리밍 텍스트 등은 "그림"으로 충분히 테스트할 수 없습니다.

**Brian의 해결책:**
> "AI 제품은 코드로 프로토타이핑하지 않으면 '현실'을 만날 수 없습니다."

- **Code-based prototyping**으로 실제 API 호출, 실시간 인터랙션을 구현하여 디자인 단계에서 이미 현실의 제약을 마주합니다.
- 이를 통해 **"Reality check"**를 앞당겨, 나중에 개발 단계에서 "이건 안 됩니다"라는 말을 듣는 일을 줄입니다.

---

### 2. 프로토타입 플레이그라운드: 팀 전체의 협업 환경

**구조:**
- **공유 Next.js 앱**: 디자이너들이 각자 독립된 레포지토리 대신 하나의 앱에서 작업
- **각 프로토타입은 개별 route**: `/podcast-player`, `/ai-assistant` 같은 경로로 접근
- **GitHub으로 협업**: Pull Request, Code Review, 배포 자동화

**효과:**
- 디자이너가 코드를 몰라도 Claude Code가 대신 작성 → **진입 장벽 제거**
- 팀원들끼리 코드 리뷰하며 학습 → **집단 지식 축적**
- 프로토타입이 살아있는 URL로 존재 → **PM, 엔지니어와 즉시 공유 가능**

---

### 3. Claude Code의 "Plan Mode": 생각 → 실행 분리

**핵심 팁:**
> "Claude에게 바로 코딩시키지 말고, 먼저 계획을 세우게 하세요."

**워크플로우:**
1. **Plan Mode 켜기**: Claude가 먼저 전체 구조, 필요한 컴포넌트, API 호출 등을 설명
2. **사람이 검토**: "이 부분은 다르게 해주세요" 같은 피드백
3. **실행**: 계획이 확정되면 Claude가 코드 작성

**왜 중요한가?**
- 한 번에 코딩하면 나중에 "아, 이렇게 안 하려고 했는데..."하는 일이 많음
- 계획 단계에서 디자이너의 의도를 명확히 전달 → **더 정확한 결과**

---

### 4. 커스텀 Slash Commands & Skills: 반복 작업 자동화

**Brian의 황금률:**
> "Claude가 당신에게 뭔가 하라고 요청하면, Claude 자체가 그걸 하도록 가르치세요."

**사례 1: `/deploy` 커맨드**
- **문제**: 프로토타입 배포할 때마다 Git add → commit → push → PR 생성을 수동으로 해야 함
- **해결**: `/deploy` 한 번으로 자동화 → 5분 작업이 10초로 단축

**사례 2: `/find-icon` 스킬**
- **문제**: 아이콘 찾아서 설치하고 import 하는 게 귀찮음
- **해결**: "find me a podcast icon" → Claude가 알아서 검색, 설치, 코드 삽입

**결과:**
- 디자이너가 코드 세부사항에 신경 쓰지 않고 **UX 디자인에만 집중**
- 반복 작업이 사라지니 **프로토타이핑 속도 3-5배 상승**

---

### 5. Figma → Code 자동 변환: 디자인을 즉시 코드로

**과정:**
1. Figma에서 디자인 완성
2. 스크린샷 찍어서 Claude에 업로드
3. "이 디자인을 Tailwind CSS로 구현해줘" → 5분 후 완성

**장점:**
- 디자이너가 Figma의 표현력을 유지하면서도 **실제 작동하는 프로토타입**을 즉시 얻음
- 엔지니어에게 "이런 느낌이에요" 대신 **"여기 링크 있습니다"**라고 공유 가능

---

### 6. 실전 팁: AI가 말을 안 들을 때

**문제:**
- Claude가 자꾸 엉뚱한 코드를 작성하거나, 내 의도를 못 알아듣는다.

**Brian의 솔루션:**
1. **더 구체적인 프롬프트**: "버튼을 예쁘게 해줘" → "Tailwind CSS로 rounded-lg, shadow-md, hover:bg-blue-600 적용해줘"
2. **예시 제공**: 기존 코드 조각을 보여주고 "이런 스타일로"
3. **대화 리셋**: 너무 꼬이면 새 대화 시작 (Context가 길어지면 Claude도 헷갈림)
4. **Plan Mode 다시 켜기**: 헤매면 다시 계획 단계로 돌아가기

---

## Context: 왜 지금 이게 중요한가?

### AI 시대의 디자이너 역할 변화

**과거 (2023년 이전):**
- 디자이너 = Figma 전문가
- 프로토타입 = 정적 화면 묶음
- 엔지니어 = "이거 구현 안 돼요" 라고 말하는 사람

**현재 (2026년):**
- 디자이너 = **코드 기반 프로토타이퍼**
- 프로토타입 = 실제 작동하는 앱
- 엔지니어 = 프로토타입을 보고 "이거 그대로 프로덕션에 넣을게요"

**핵심:**
> AI 제품 시대에는 **UX를 코드로 표현하는 능력**이 필수입니다. Figma로는 "AI가 생각하는 시간", "스트리밍 응답 속도", "에러 복구 시나리오"를 테스트할 수 없습니다.

---

### 개발자에게 주는 시사점

**1. 디자이너가 코드를 이해하기 시작했다**
- 디자이너-개발자 간 "불가능해요" 논쟁이 줄어듦
- 디자이너가 이미 프로토타입으로 "가능함"을 증명

**2. 프로토타입 = MVP 초안**
- 디자이너가 만든 프로토타입 코드를 그대로 프로덕션에 쓸 수 있음
- 개발자는 "구조 개선, 최적화, 보안" 같은 고급 작업에 집중

**3. AI 코딩 도구는 "코딩 못하는 사람"을 위한 게 아니라 "빠르게 실험하고 싶은 사람"을 위한 것**
- 숙련된 개발자도 반복 작업을 AI에 맡기고, 핵심 로직/아키텍처에 집중

---

## Application: 개발자로서 어떻게 적용할 것인가?

### 1. beauty-sale에 적용: AI 기반 프로토타이핑 도입

**시나리오:**
- 새 기능 (예: 가격 알림 설정 UI) 디자인할 때

**Before (기존 방식):**
1. Figma로 디자인 → 2시간
2. 개발자가 코드 작성 → 4시간
3. PM/디자이너 피드백 → 수정 1시간
4. 다시 개발 → 2시간
**총 9시간**

**After (AI 프로토타이핑):**
1. Claude Code로 프로토타입 작성 → 30분
2. PM/디자이너와 실제 동작 확인 → 20분
3. 피드백 반영 → 10분
4. 프로토타입 코드를 프로덕션에 리팩토링 → 1시간
**총 2시간**

**효과:**
- **속도 4-5배 향상**
- **"불가능해요" 논쟁 제거** (이미 작동하는 걸 보여줬으니)

---

### 2. 커스텀 Claude Skills 만들기

**beauty-sale용 스킬 예시:**
- `/deploy-staging`: 스테이징 서버 배포 자동화
- `/run-price-check`: 가격 크롤링 스크립트 실행
- `/find-mui-component`: Material-UI 컴포넌트 검색 & import

**작성 방법:**
- `~/.openclaw/workspace/skills/beauty-sale-utils/SKILL.md` 생성
- Claude Code가 참조할 명령어, 스크립트, API 엔드포인트 정리
- 반복 작업이 나올 때마다 스킬로 등록

---

### 3. 이직 면접에서 활용

**면접관이 좋아하는 스토리:**
> "저는 디자이너와 협업할 때 Claude Code를 활용해 프로토타입을 30분 안에 만들어서 공유했습니다. 이를 통해 요구사항 오해를 사전에 방지하고, 개발 사이클을 50% 단축했습니다."

**추가 포인트:**
- "AI 도구를 단순히 코드 생성용이 아니라, **팀 협업 속도 향상**에 활용했다"는 게 핵심
- "프로덕트 엔지니어"로 포지셔닝: 기술 + 제품 감각 + AI 활용

---

### 4. 학습 루틴에 반영

**화요일 AI 학습 시간 (1시간):**
- **Week 1**: Claude Code로 간단한 대시보드 프로토타입 만들기
- **Week 2**: 커스텀 slash command 만들기
- **Week 3**: Figma 디자인을 Claude Code로 변환 실습
- **Week 4**: beauty-sale에 실제 적용할 프로토타입 1개 구현

## 🤔 생각해볼 질문

1. **우리 팀에서 프로토타이핑 속도를 10배 높이려면?**
   - 현재 디자인 → 개발 → 피드백 사이클이 며칠 걸리는가?
   - Claude Code로 디자이너가 직접 프로토타입을 만들면?

2. **코드 품질 vs 속도 트레이드오프를 어떻게 관리할 것인가?**
   - AI가 생성한 코드는 "빠르게 만든 초안"
   - 프로덕션에 넣기 전 리팩토링, 테스트 코드, 보안 검토 필요

3. **AI 도구가 디자이너-개발자 경계를 어떻게 바꾸고 있나?**
   - 디자이너가 코드를 쓰기 시작하면, 개발자의 역할은?
   - → **더 높은 수준의 아키텍처, 성능 최적화, 인프라 설계**로 이동
