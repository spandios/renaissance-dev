## 🎯 The Big Idea

> **"AI 시대, 소프트웨어 회사는 살아남을 수 있다. 하지만 경쟁의 본질이 바뀌었다."**

Microsoft는 ChatGPT 출시 직후 가장 큰 수혜자로 여겨졌지만, 이제는 가장 큰 위협을 받고 있다. Azure 성장 둔화로 $357B 시가총액이 증발했고, 이 사건은 단순한 실적 쇼크가 아니라 **AI 시대 소프트웨어 비즈니스의 본질적 변화**를 드러낸다.

핵심 질문: **"AI가 코드를 쓴다면, 소프트웨어 회사는 왜 필요한가?"**

### 2. AI 시대, 소프트웨어는 살아남을 수 있는가?

**Bear Case (비관론)**
> "AI가 코드를 쓴다면, 왜 소프트웨어를 사야 하나? 그냥 AI한테 시켜서 내 맞춤형 앱을 만들면 되잖아?"

**Ben Thompson의 Bull Case (낙관론)**

**이유 1: 코어 역량 집중 (Core Competency)**
- 대부분 회사의 코어 비즈니스는 소프트웨어가 아니다
- 미국 기업들은 특히 아웃소싱을 잘한다
- 소프트웨어 개발은 비즈니스의 핵심이 아닌 한 외주가 합리적

**이유 2: 유지보수는 끝없는 여정 (Never-Ending Journey)**
- 코드 작성은 시작일 뿐
- 유지보수, 보안 패치, 새 기능, 표준 변경
- 영원한 커밋먼트 = 코어 비즈니스가 아니면 부담

**이유 3: 소프트웨어 ≠ 코드 (Software ≠ Code)**
- 고객 지원
- 컴플라이언스
- 다른 소프트웨어와의 통합
- 가치는 코드를 넘어선다
- 이게 기업들이 오픈소스를 안 쓰는 이유: 코드가 아니라 **제품**을 원한다

**결론**: 소프트웨어 회사는 **AI로 코드를 쓰는 가장 큰 수혜자**가 될 것이다. 더 빠르고 효율적으로 더 많은 코드를 쓸 수 있다.

### 3. AI 경쟁: 출판사의 비극이 재현된다

**인터넷 시대 출판사의 역설**
- 전 세계가 독자 = 엄청난 기회처럼 보였다
- 하지만 모든 출판사가 전 세계에 배포 가능 = 경쟁 폭발
- **배포 비용이 0이 되면서 경쟁 환경이 정반대로 바뀜**
- 결과: Google 같은 애그리게이터가 모든 파워를 가져감

**AI 시대 소프트웨어의 역설**
- **코드 작성 비용이 0에 가까워짐**
- 한 회사에게는 좋지만, 모든 회사가 같은 혜택을 받음
- **무한한 소프트웨어 작성 능력** = 경쟁 폭발

**결과 예측**
- **지난 10년 (2014-2024)**: SaaS는 "파이 키우기" 게임
  - 비즈니스 기능 하나 찾기 → 오픈소스로 SaaS 앱 만들기 → 영업팀 고용 → 코호트 분석 → IPO
- **다음 10년 (2026-2036)**: "파이 싸움" 게임
  - 기업들은 더 많은 소프트웨어를 사고 싶어하지 않음 (토큰에 돈 써야 함)
  - 성장 스토리 종료 → 인접 영역 공격 시작
  - **AI 모델 제공자들이 무기 상인**

### 4. 에이전트 시대와 Work IQ

**Microsoft의 전략: Work IQ**
- Microsoft 365 데이터 위에 stateful agent 구축
- 사람, 역할, 아티팩트, 커뮤니케이션, 히스토리, 메모리 → 조직의 보안 경계 내에서 추론
- **Active Directory의 후계자**: 개인 근로자와 모든 아티팩트, 권한을 이해
- M365 Copilot 대화 횟수 YoY 2배 증가

**문제점**
- **ID 기반 모델은 줄어들고 있다**: 인간 ID가 줄어들면 per-seat 라이선스 수익도 줄어든다
- **따라서 Microsoft는 공격적으로 인접 영역을 흡수해야 한다**:
  1. 더 많은 비즈니스 기능 통합 → 에이전트 능력 향상
  2. 더 넓은 영역 = 더 높은 가격 책정
  3. 더 큰 표면적 = 다른 소프트웨어가 Microsoft 에이전트와 연동하도록 강제력 확보

### 5. Microsoft의 실책과 용량 할당 결정

**Azure 미달의 진실**

CFO Amy Hood:
> "수요는 공급을 초과합니다. 하지만 우리는 균형을 맞춰야 합니다."

**GPU 할당 우선순위**
1. M365 Copilot, GitHub Copilot (자사 제품)
2. R&D 팀 (제품 혁신 가속)
3. 수명 종료 서버/네트워크 교체
4. 마지막: Azure 고객

Hood:
> "Q1-Q2에 온라인된 GPU를 전부 Azure에 할당했다면, KPI는 40% 이상이었을 것입니다."

**Nadella의 포트폴리오 접근**
- Azure 고객 확보도 중요하지만, M365/GitHub/Dragon Copilot 고객 확보도 중요
- 모두 증분 비즈니스이고 새로운 TAM (Total Addressable Market)
- **LTV (Lifetime Value) 포트폴리오 최적화**: Azure보다 생산성 앱이 마진과 LTV가 더 높음
- "한 비즈니스만 최대화하지 않는다. 장기적으로 최고의 LTV 포트폴리오를 구축한다."

**Thompson의 판단**: **이것은 옳은 결정이었다.**
- Microsoft가 자사 소프트웨어에서 AI를 제대로 구현하지 못하면, 경쟁자들이 곧 침입할 것
- R&D도 중요: AI로 새 소프트웨어를 쓰려면 엄청난 GPU 필요
- Wall Street 예상치 충족보다 장기 경쟁력이 우선

### 6. Token Foundry 개념과 Pure Play 클라우드의 부상

**문제점**: Azure는 "Pure Play Foundry"가 아니다

**TSMC 이전 시대**
- 통합 반도체 제조사 (Intel, TI): 파운드리를 가지고 있었지만, 자사 제품 우선
- 외부 고객이 용량을 빌려도, 자사 제품이 필요하면 빼앗길 수 있었음
- **TSMC의 차별점**: 순수 파운드리, 고객과 경쟁하지 않음, 100% 고객 우선

**Microsoft의 우선순위**
1. Microsoft 자사 제품
2. OpenAI (45% RPO)
3. 나머지 고객

→ **이번 분기에 이 우선순위가 명확히 드러남**

**시사점**
- Amazon, Google도 비슷한 우선순위 결정을 내릴 것
- **Neoclouds (Oracle 등)의 기회**: "Pure Play Token Foundry"로 차별화
- 자사 제품과 경쟁하지 않는 클라우드 = 새로운 가치 제안

## 🌍 Context: 이 글이 왜 지금 중요한가?

### 1. AI 시대 소프트웨어 비즈니스 모델의 대전환
- SaaS 황금기 (2014-2024) 종료
- "성장 스토리"에서 "생존 싸움"으로 전환
- 모든 소프트웨어 회사는 AI로 무한 코드 작성 가능 → 차별화 어려움

### 2. GPU 부족이 만드는 새로운 게임 이론
- 클라우드 제공자는 더 이상 중립적이지 않다
- 자사 우선 정책 = 고객 실망 = Pure Play 기회
- TSMC의 CapEx 보수성이 칩 부족을 악화시킬 것

### 3. Per-Seat 라이선스 모델의 종말 예고
- 에이전트가 일을 하면, 인간 좌석 수는 줄어든다
- Microsoft의 수익 모델이 근본적으로 위협받음
- 새로운 가격 모델 필요

### 4. 개발자로서의 시사점
- **소프트웨어 회사는 살아남지만, 경쟁은 치열해진다**
- AI로 코드를 잘 쓰는 회사가 승자
- 인접 영역 공격이 일상화될 것
- "Arms Dealer" (AI 모델 제공자)가 가장 큰 승자

## 💼 Application: 개발자로서 어떻게 적용할 것인가?

### 1. "Software Survival" 관점에서 이직 전략 재구성

**핵심 질문**
> "내가 지원하는 회사는 AI 시대에 살아남을 수 있는가?"

**체크리스트**
- [ ] 회사가 코어 비즈니스에 집중하고 있는가? (아니면 무분별한 SaaS 확장?)
- [ ] AI로 코드 작성 능력을 확보하고 있는가? (내부 엔지니어링 역량)
- [ ] 인접 영역 공격 전략이 있는가? (방어적 확장)
- [ ] Per-seat 라이선스 의존도는? (에이전트 시대 리스크)
- [ ] 제품의 "코드 너머 가치"는 무엇인가? (지원, 통합, 컴플라이언스)

**이직 타겟 회사 재평가**
- ❌ **피해야 할 회사**: 단순 SaaS, AI 전략 없음, 좁은 기능만 제공
- ✅ **선호해야 할 회사**:
  - AI-native 제품 개발 중
  - 넓은 플랫폼 (인접 영역 흡수 능력)
  - 강력한 네트워크 효과 또는 데이터 moat
  - 클라우드 인프라 (Token Foundry 또는 AI 모델 제공자)

### 2. "AI Arms Dealer" 관점에서 경력 방향 설정

**Ben Thompson의 핵심 통찰**
> "다음 10년은 파이 싸움. AI 모델 제공자들이 무기 상인."

**개발자로서의 선택지**

**Option 1: Arms Dealer가 되기**
- AI 모델 개발 (LLM, 코드 생성 모델)
- AI 인프라 (토큰 최적화, 추론 효율화)
- AI 도구 개발 (Claude Code, Codex 같은 개발 도구)
- **장점**: 모든 소프트웨어 회사가 고객
- **단점**: 초고난도, 자본 집약적

**Option 2: Arms Dealer의 고객이 되기 (현실적)**
- AI로 코드를 잘 쓰는 개발자
- AI 도구를 팀에 도입하고 최적화하는 리더
- AI 시대의 "소프트웨어 아키텍트"
- **장점**: 당장 적용 가능, 경쟁력 확보
- **단점**: 계속 학습 필요, 빠르게 진화 중

**Option 3: Pure Play를 노리기**
- Neocloud 같은 "순수한" 서비스 제공자
- 고객과 경쟁하지 않는 포지션
- **장점**: Microsoft/AWS의 자사 우선 정책으로 기회 생김
- **단점**: 자본 필요, 경쟁 치열

### 3. beauty-sale 프로젝트에 적용

**현재 상황 분석**
- 소규모 팀, 유일한 기술 전문가
- K-뷰티 가격 비교 앱
- Spring Boot, Kotlin, React

**"Software Survival" 렌즈로 본 beauty-sale**

**강점**
- ✅ **코어 비즈니스 명확**: 가격 비교 = 핵심 가치
- ✅ **AI로 확장 가능**: 가격 예측, 리뷰 분석, 개인화 추천
- ✅ **코드 너머 가치**: 신뢰할 수 있는 데이터, 실시간 업데이트

**리스크**
- ⚠️ **AI가 대체 가능**: "Claude한테 물어봐서 가장 싼 곳 찾기"
- ⚠️ **네트워크 효과 약함**: 사용자 간 상호작용 없음
- ⚠️ **인접 영역 확장 어려움**: 가격 비교를 넘어선 확장이 불명확

**생존 전략**
1. **AI 에이전트 통합**
   - "내가 원하는 제품을 가장 싸게 사는 방법 알려줘"
   - 자동 가격 추적 + 알림
2. **인접 영역 공격**
   - 가격 비교 → 리뷰 통합 → 큐레이션 → 구매 대행
3. **데이터 Moat 강화**
   - 실시간 가격 히스토리
   - 신뢰도 점수
   - 플랫폼별 특가 패턴 학습

### 4. 이직 면접에서 활용

**질문 1: "AI 시대에 소프트웨어 엔지니어의 역할은 무엇이라고 생각하나요?"**

**나쁜 답변**
> "AI가 코드를 쓰면 우리는 필요 없을 것 같습니다."

**좋은 답변** (Ben Thompson 기반)
> "AI가 코드를 쓰는 시대에도 소프트웨어 회사는 살아남습니다. 왜냐하면 기업들은 코드가 아니라 제품을 원하기 때문입니다. 유지보수, 보안, 통합, 지원 등 코드 너머의 가치가 핵심입니다. 개발자의 역할은 'AI로 코드를 잘 쓰는 아키텍트'로 진화할 것입니다. 저는 beauty-sale에서 AI를 활용해 가격 예측 기능을 개발했고, 이를 통해 개발 속도를 2배 높였습니다."

**질문 2: "우리 회사가 AI 시대에 경쟁력을 확보하려면 무엇을 해야 할까요?"**

**나쁜 답변**
> "AI 기능을 추가하면 됩니다."

**좋은 답변** (Ben Thompson 기반)
> "세 가지가 중요합니다. 첫째, AI로 코드를 빠르게 작성하는 내부 역량 확보. 둘째, 인접 영역으로 공격적 확장 (모든 회사가 AI로 무한 소프트웨어를 만들 수 있으므로, 파이 싸움이 시작됨). 셋째, 에이전트 시대를 대비한 비즈니스 모델 전환 (per-seat 라이선스는 인간 수가 줄면 위험). 예를 들어 beauty-sale에서는 가격 비교를 넘어 리뷰 분석과 개인화 추천으로 확장할 계획입니다."

## 📌 Key Takeaways

1. **소프트웨어 회사는 살아남지만, 경쟁이 치열해진다**
   - AI로 모든 회사가 무한 코드 작성 가능
   - 코드 너머의 가치 (지원, 통합, 컴플라이언스)가 핵심

2. **AI 시대는 "파이 키우기"에서 "파이 싸움"으로**
   - 인접 영역 공격이 일상화
   - AI 모델 제공자들이 무기 상인

3. **Microsoft의 용량 할당 결정은 옳았다**
   - 장기 LTV 포트폴리오 최적화 > 단기 Azure 성장률
   - 자사 제품에 AI를 제대로 구현하지 못하면, 경쟁자 침입

4. **Pure Play Token Foundry의 부상**
   - 클라우드는 더 이상 중립적이지 않음
   - 자사 우선 정책 = Neocloud 기회

5. **개발자로서의 생존 전략**
   - AI로 코드를 잘 쓰는 능력 필수
   - "소프트웨어 아키텍트"로 진화
   - AI-native 제품 개발 회사로 이직
