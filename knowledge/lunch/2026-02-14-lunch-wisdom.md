## 1. The Big Idea (핵심 관통하기)

**AI가 코드 작성 비용을 0에 수렴시키면서, 소프트웨어 기업의 생존 전략은 "더 넓은 영역을 먹는 것"으로 바뀌고 있다. Microsoft는 이 전쟁에서 Azure 성장을 희생하면서까지 자사 AI 제품에 GPU를 우선 배분하는 선택을 했다.**

---

## 2. Argument Breakdown (논리 해부)

### 2-1. AI 시대 빅테크의 순환적 위기

Ben Thompson은 ChatGPT 이후 빅테크가 순환적으로 위기에 처했다고 정리한다:
- **2023:** Google (검색 disruption 우려)
- **2025 초:** Apple (Siri 실패)
- **2025 하반기:** Meta (Llama 한계)
- **2026:** Microsoft (Azure 성장 둔화 + $357B 시총 증발)

Microsoft는 원래 OpenAI 파트너십 덕에 AI 최대 수혜자로 보였지만, 지금은 오히려 OpenAI가 Azure RPO의 45%를 차지한다는 점이 리스크로 인식된다.

### 2-2. AI가 코드를 쓰면 소프트웨어 기업은 죽는가?

Thompson의 답: **아니다.** 세 가지 이유:

1. **핵심 역량 집중:** 대부분의 기업은 소프트웨어가 본업이 아님. AI로 코드를 쓸 수 있어도, 소프트웨어 "제품"을 운영하는 건 다른 문제.
2. **유지보수의 끝없는 여정:** 앱을 만드는 건 시작일 뿐. 보안 패치, 새 기능, 표준 변경 — 이건 끝나지 않는 여정.
3. **코드 ≠ 제품:** 지원, 컴플라이언스, 통합 — 기업이 원하는 건 코드가 아니라 완전한 제품.

**결론:** 소프트웨어 기업 자체가 AI 코딩의 최대 수혜자. 더 빠르고 효율적으로 코드를 써서 경쟁할 수 있다.

### 2-3. 인터넷-미디어 비유: 진짜 위험은 경쟁 격화

여기서 Thompson의 핵심 통찰이 나온다. 인터넷이 미디어에 한 것과 AI가 소프트웨어에 하는 것의 비유:

- **인터넷 → 미디어:** 배포 비용 0 → 개별 출판사에겐 좋지만, 업계 전체에겐 재앙 (과잉 공급)
- **AI → 소프트웨어:** 코드 비용 0에 수렴 → 개별 기업은 더 많이 만들 수 있지만, 모든 경쟁자도 마찬가지

**실질적 위협:** SaaS 기업들이 서로의 영역을 침범하는 전면전. 지난 10년이 "파이를 키우는" 시대였다면, 앞으로 10년은 "파이를 빼앗는" 시대. 모델 메이커들은 무기상이 된다.

### 2-4. Agent와 Work IQ: Microsoft의 베팅

Microsoft는 **Work IQ**라는 개념으로 승부한다:
- Microsoft 365 아래의 데이터(사람, 역할, 문서, 커뮤니케이션)를 활용한 stateful agent
- Active Directory라는 킬러 자산: 기업 내 identity 소유

**그러나 모순이 있다:** per-seat 라이센싱 모델인데, AI가 인간 identity 수를 줄이면? → Microsoft는 더 많은 비즈니스 기능을 흡수해야 하는 압박.

### 2-5. Azure Miss의 진짜 이유: 의도적 GPU 배분

Microsoft CFO Amy Hood의 설명:
- 들어오는 GPU를 Azure에 다 할당했다면 성장률 40%+ 달성 가능했음
- 하지만 M365 Copilot, GitHub Copilot, R&D에 우선 배분
- Nadella: "하나의 사업을 최적화하는 게 아니라 포트폴리오 LTV를 최적화"

**Thompson의 판단:** 올바른 결정. Azure 매출보다 자사 AI 제품의 마진과 LTV가 더 높다.

### 2-6. Token Foundry 개념의 등장

Microsoft가 자사 우선으로 GPU를 쓴다는 건 Azure 고객에겐 불안 요소. 이는 TSMC 이전의 IDM 시대와 비슷:
- Intel의 팹에서 생산하면, Intel 자사 제품이 우선
- TSMC가 "순수 파운드리"로 혁명을 일으킨 것처럼
- **Neocloud나 Oracle이 "순수 토큰 파운드리"로 가치를 가질 수 있다**

## 3. Why It Matters (왜 중요한가)

### 시장 관점
- SaaS 업계의 밸류에이션 재조정은 정당하다. AI가 코드 비용을 낮추면서 진입장벽이 무너지고 있다.
- Big Tech의 CapEx 경쟁은 단순한 인프라 투자가 아니라 "소프트웨어 전쟁의 군비 경쟁"이다.
- per-seat → per-agent 라이센싱 전환이 소프트웨어 비즈니스 모델의 다음 대전환.

### 기술 트렌드
- **AI 코딩 도구의 위치:** 코드를 쓰는 건 점점 쉬워지지만, 소프트웨어 "제품"을 만드는 건 여전히 어렵다. 아키텍트의 역할이 더 중요해진다.
- **Agent 시대:** 소프트웨어의 사용자가 인간에서 agent로 확장되면서, API/통합 레이어의 가치가 급상승.
- **Token Foundry:** 클라우드의 다음 진화 — 중립적 GPU 인프라 제공자의 가치.

## 4. 💼 For Engineers (개발자에게)

### ① "코드를 쓴다"는 것의 가치 재정의
AI가 코드를 쓰는 시대에, 개발자의 가치는 코드 작성 속도가 아니라 **무엇을 만들지 결정하는 능력**에 있다. Thompson이 말한 "소프트웨어 아키텍트의 역할이 좀 더 오래 중요할 것"이라는 표현에 주목. **시스템 설계, 제품 판단, 비즈니스 이해**가 차별화 요소.

### ② SaaS 전면전에서의 포지셔닝
beauty-sale 같은 프로젝트를 생각할 때: 단일 기능 앱은 점점 위험해진다. **인접 영역 확장**이 생존 전략. 가격 비교 → 구매 → 리뷰 → 커뮤니티로 이어지는 풀스택 경험을 설계해야 한다.

### ③ Agent-First 설계
소프트웨어의 사용자가 agent가 되는 미래를 대비하라. API를 먼저 설계하고, UI는 그 위의 레이어로 취급하라. MCP/tool-use 패턴에 익숙해지는 것이 실무적으로 가장 빠른 준비.

### ④ "토큰 파운드리" 마인드셋
GPU/토큰 비용은 새로운 COGS다. 앱을 설계할 때 토큰 효율성을 아키텍처 레벨에서 고려하라. 캐싱, 모델 라우팅, 비용 최적화가 인프라 엔지니어링의 핵심 역량이 된다.
