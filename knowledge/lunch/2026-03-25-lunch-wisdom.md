# AI 에이전트 시장의 기회: 왜 모두가 코딩에만 몰릴까?

**출처**: [Anthropic AI 에이전트 사용 연구 분석](https://news.hada.io/topic?id=26915) (GeekNews)  
**작성일**: 2026-03-25

---

## 🎯 The Big Idea

**"AI 에이전트 시장의 절반은 소프트웨어 엔지니어링이 차지하고, 나머지 16개 버티컬(헬스케어, 법률, 금융 등)은 각각 5% 미만이다. 이것은 포화가 아니라 미개척 상태다."**

Anthropic의 실제 사용 데이터가 보여주는 것은 명확하다: 모두가 AI 코딩 에이전트에 몰려 있지만, 정작 거대한 기회는 **아무도 손대지 않은 버티컬 AI**에 있다.

---

## 📊 Argument Breakdown

### 1. 소프트웨어 엔지니어링의 독점: 49.7% vs. 나머지 버티컬 < 5%

Anthropic의 데이터에 따르면:
- 소프트웨어 엔지니어링이 **전체 에이전트 도구 호출의 49.7%** 차지
- 헬스케어 1%, 법률 0.9%, 교육 1.8%...
- 16개 버티컬 중 **9%를 넘는 분야가 단 하나도 없음**

Y Combinator의 Garry Tan은 이렇게 말했다:
> "지금 창업한다면 [붉은 영역](AI 에이전트 차트의 버티컬 영역)을 주시해야 한다."

**이것이 의미하는 것:**
- 코딩 에이전트 시장은 이미 **경쟁 과밀** 상태 (Cursor, Claude Code, GitHub Copilot, Codex...)
- 반면 헬스케어, 법률, 금융 등은 **사실상 시장이 형성되지 않음**
- 이것은 "포화가 아니라 기회"의 신호

---

### 2. 배포 격차 (Deployment Overhang): AI는 5시간 일할 수 있지만, 사용자는 42분만 허용

METR 평가:
- Claude 모델은 **인간이 5시간 걸릴 작업 수행 가능**
- 하지만 실제 사용자는 평균 **42분만 허용** (99.9번째 백분위 기준)
- 2025년 10월 → 2026년 1월: 25분 → 45분으로 증가 (거의 두 배)

**왜 이런 격차가 발생하나?**
- 모델 성능 향상만이 아니라 **사용자 신뢰 축적**의 결과
- 사용자 경험 증가 → 자동 승인률 20% → 40% 상승
- 내부 데이터: Claude Code 성공률 2배 증가, 인간 개입 5.4회 → 3.3회 감소

**핵심 통찰:**
> "AI가 할 수 있는 것"과 "사용자가 허용하는 것" 사이의 격차가 곧 **제품 기회**다.

---

### 3. 신뢰의 진화: 사전 승인 → 능동적 모니터링

**신규 사용자:**
- 세션의 **20%만 자동 승인**
- 개입률 **5%**
- 전략: **각 단계를 사전 승인** (Step-by-step)

**숙련 사용자 (750회+ 세션):**
- 세션의 **40% 이상 완전 자동 승인**
- 개입률 **9%** (더 많이 개입!)
- 전략: **위임 후 문제 발생 시 개입** (Delegate and Monitor)

**반직관적 발견:**
숙련자가 개입을 "덜" 하는 것이 아니라 "더 많이" 하는 이유는?
→ 감독 전략의 변화: **"사전 승인" → "능동적 모니터링"**

**안전성 발견:**
- 복잡한 작업에서 Claude Code는 인간보다 **2배 이상 확인 질문 제기**
- 에이전트가 무작정 진행하지 않고 **불확실할 때 스스로 멈춤**

**Anthropic의 교훈:**
> "자율성은 모델의 고유 속성이 아니라, 모델·사용자·제품이 공동으로 구성하는 것이다."

---

### 4. Aaron Levie의 버티컬 AI 플레이북: 래퍼가 아니라 방어력

Box CEO Aaron Levie가 제시하는 **방어 가능한 버티컬 AI 공식**:

1. **독점 데이터 연결**: 고유한 산업 데이터에 에이전트 연동
2. **도메인 특화 컨텍스트 엔지니어링**: 출력 지능 극대화
3. **워크플로 자동화**: 실제 사람과 문제에 맞게 설계
4. **변화 관리 (Change Management)**: 고객 조직의 마찰 해결

**왜 버티컬 AI는 방어 가능한가?**
- 누구나 **래퍼(wrapper)**는 만들 수 있다 (GPT API 호출)
- 하지만 **헬스케어 청구, 법률 디스커버리, 건설 허가** 등의:
  - 구체적 워크플로
  - 규제 제약
  - 조직 마찰
- 이것들을 탐색할 수 있는 곳은 **소수**

**SaaS의 교훈:**
- 지난 20년간 **170개+ SaaS 유니콘** 배출
- VC 투자금의 **40% 이상이 SaaS에 집중**
- 각 SaaS 유니콘마다 **대응하는 버티컬 AI 유니콘** 가능성 존재

**핵심 테제:**
> "버티컬 AI는 소프트웨어뿐 아니라 **운영자까지 대체**하기 때문에 SaaS보다 **10배 더 클 수 있다**."

## 🌍 Context: 왜 지금 중요한가?

### 1. 코딩 에이전트 시장의 과열

**현재 상황:**
- Cursor, Claude Code, GitHub Copilot, Codex, Windsurf, Aider... 
- 모두가 코딩 에이전트에 몰려 있음
- 시장 점유율 **49.7%** → 이미 경쟁 과밀

**시장 시사점:**
- "첫 번째 물결"은 이미 지나감
- 코딩 에이전트는 **인프라화** (Commoditization) 진행 중
- 차별화 요소: 성능이 아니라 **UX, 워크플로 통합**

---

### 2. 버티컬 AI의 블루오션

**헬스케어 (1%):**
- 의료 기록 분석, 청구 자동화, 진단 보조
- 규제: HIPAA, FDA 승인
- 데이터: EMR/EHR 통합

**법률 (0.9%):**
- 계약서 검토, 법률 리서치, 디스커버리 자동화
- 규제: 변호사-의뢰인 특권, 증거 규칙
- 데이터: 판례, 계약서 템플릿

**금융 (< 5%):**
- 신용 평가, 사기 탐지, 투자 분석
- 규제: SEC, FINRA, GDPR
- 데이터: 거래 기록, 시장 데이터

**교육 (1.8%):**
- 개인화 학습, 과제 채점, 커리큘럼 설계
- 데이터: 학습 기록, 평가 결과

**핵심:**
- 각 버티컬은 **고유한 데이터, 워크플로, 규제**를 가짐
- 이것이 곧 **진입 장벽**이자 **방어력**

---

### 3. "배포 격차"가 의미하는 것

**AI 성능:**
- 모델은 이미 **5시간 작업 가능**
- Claude Code 성공률 **2배 증가**

**사용자 신뢰:**
- 하지만 평균 **42분만 허용**
- 신뢰 축적 = **시간 + 경험**

**시장 기회:**
- "AI가 할 수 있는 것"과 "사용자가 허용하는 것" 사이의 격차
- 이 격차를 줄이는 제품 = **UX, 투명성, 감독 도구**
- 버티컬 AI는 이 격차가 **훨씬 큼** (신뢰 구축이 더 어려움)

---

## 💡 Application: 개발자로서 어떻게 적용할 것인가?

### 1. 코딩 에이전트에만 의존하지 마라

**현실:**
- 코딩 에이전트 시장은 이미 **과밀**
- Cursor, Claude Code, Copilot이 치열하게 경쟁 중
- 성능 차이는 점점 줄어듦

**대안:**
- **버티컬 AI 기회 탐색**: 내가 경험한 도메인이 있는가?
  - 의료, 법률, 금융, 물류, 교육, 고객 서비스...
  - 내가 아는 워크플로의 pain point는?
- **"래퍼가 아니라 방어력"**: 단순 API 호출이 아니라
  - 독점 데이터 연결
  - 도메인 컨텍스트 엔지니어링
  - 변화 관리 (조직 마찰 해결)

---

### 2. "배포 격차"를 줄이는 제품 만들기

**사용자 신뢰 구축 전략:**

1. **투명성**: AI가 무엇을 하는지 명확히 보여줘라
   - 실시간 로그, 의사결정 과정 시각화
   - 예: Claude Code의 "확인 질문" 메커니즘

2. **점진적 자율성**: 처음엔 사전 승인, 익숙해지면 자동화
   - 사용자가 **신뢰 레벨을 조절**할 수 있게
   - 예: "이 작업은 자동 승인, 저 작업은 확인 필요"

3. **능동적 모니터링 도구**: 위임 후 문제 발생 시 개입
   - 알림, 대시보드, 롤백 기능
   - 예: "AI가 이상한 행동을 했을 때 즉시 알림"

4. **안전 장치 (Guardrails)**: AI가 위험한 행동 전에 멈추기
   - 규칙 기반 제약
   - 예: "고객 데이터 삭제 전 확인", "API 키 노출 방지"

---

### 3. 버티컬 AI 창업 체크리스트 (Aaron Levie 공식)

**스스로 질문하기:**

1. **도메인 전문성**: 내가 이 산업의 pain point를 깊이 이해하는가?
   - 5년+ 경력? 직접 겪은 문제?
   - 단순 "관찰"이 아니라 "체득"한 지식인가?

2. **독점 데이터 접근**: 이 산업의 고유한 데이터에 연결할 수 있는가?
   - EMR, 법률 문서, 금융 거래 기록...
   - 파트너십, API, 직접 통합?

3. **워크플로 자동화**: 실제 사람들이 사용할 워크플로를 설계했는가?
   - 단순 챗봇이 아니라 **end-to-end 자동화**
   - 예: "의료 청구 → 보험 승인 → 결제" 전체 프로세스

4. **규제 이해**: 이 산업의 규제를 준수할 수 있는가?
   - HIPAA, GDPR, FDA, SEC...
   - 법률 자문, 인증 과정?

5. **변화 관리**: 고객 조직이 AI를 채택하도록 도울 수 있는가?
   - 교육, 온보딩, 문화 변화
   - "기술만이 아니라 사람의 문제"

**만약 5개 중 3개 이상 "아니오"라면:**
→ 코딩 에이전트 시장보다 더 어려울 수 있음
→ 코딩 에이전트는 최소한 "개발자 = 얼리 어답터"라는 이점이 있음

---

### 4. 장기적 관점: SaaS → 버티컬 AI

**SaaS의 교훈:**
- 지난 20년간 **170개 유니콘** 배출
- 각 산업마다 SaaS 솔루션 등장 (Salesforce, Workday, Epic, Clio...)

**버티컬 AI의 미래:**
- 각 SaaS 유니콘마다 **AI 버전**이 등장할 가능성
- 왜 더 클까? **소프트웨어 + 운영자 대체**
- 예:
  - Salesforce (CRM) → AI 영업 에이전트
  - Epic (EMR) → AI 의료 기록 분석
  - Clio (법률 관리) → AI 계약서 검토

**핵심:**
> "향후 10년의 엔터프라이즈 소프트웨어는 버티컬을 선택하고, 도메인 전문성을 에이전트에 내장하며, 변화 관리를 해결하는 창업자가 소유할 것이다."

## 🔑 Key Takeaways

1. **AI 에이전트 시장의 절반은 코딩, 나머지는 미개척**: 헬스케어, 법률, 금융 등 각 < 5%
2. **배포 격차 = 제품 기회**: AI는 5시간 일할 수 있지만, 사용자는 42분만 허용
3. **신뢰의 진화**: 사전 승인 → 능동적 모니터링 (숙련자일수록 더 많이 개입)
4. **버티컬 AI의 방어력**: 독점 데이터 + 도메인 컨텍스트 + 워크플로 + 변화 관리
5. **SaaS의 교훈**: 170개 유니콘 → 300개 버티컬 AI 유니콘 가능성
