# Microsoft and Software Survival

**출처:** [Stratechery - Ben Thompson](https://stratechery.com/2026/microsoft-and-software-survival/)  
**날짜:** 2026년 3월 10일  
**주제:** AI 시대, 소프트웨어 산업의 생존 전략, Microsoft의 위기와 기회

---

## 🎯 The Big Idea

**AI는 소프트웨어를 죽이는 것이 아니라, 소프트웨어 산업의 구조를 근본적으로 재편하고 있다.**  
Microsoft는 더 이상 AI의 최대 수혜자가 아니다. 오히려 AI 코드 생성으로 인한 SaaS 생태계의 붕괴와 에이전트 경쟁에서 살아남기 위해 고군분투하는 중이다.

## 📊 Argument Breakdown

### 1. AI 시대, 위협받는 기업들의 순서

AI가 등장한 이후 빅테크 중 누가 가장 위협받는지에 대한 논의가 계속 변화했다:

- **2022년 말 (ChatGPT 출시):** Google과 검색 엔진
- **2025년 초:** Apple과 Siri
- **2025년 가을:** Meta와 Llama의 한계
- **2026년 초:** **Microsoft** ← 현재 여기

Microsoft는 초기에 OpenAI 파트너십 덕분에 최대 수혜자로 여겨졌다. 하지만:

- OpenAI는 Azure 매출의 45%를 차지하지만, 이제는 **부담**으로 인식됨
- Bing은 잠깐 흥미로웠으나 (Sydney 사건), 곧 잊혀짐
- Microsoft 365 Copilot은 1,500만 유료 사용자이지만, 전체 고객 기반 대비 극소수
- Agent 시대의 도래로 **좌석당 라이선스 모델의 장기적 생존 가능성에 의문**

결과: **Microsoft 주가 하루에 10% 폭락, 시가총액 3,570억 달러 증발** (2026년 1월 29일)

### 2. AI 코드 작성의 수혜자는 누구인가?

**질문:** AI가 코드를 작성하면, 소프트웨어 회사는 쓸모없어지는가?

**답:** 아니다. 오히려 소프트웨어 회사가 가장 큰 수혜자다.

#### 왜 소프트웨어는 사라지지 않는가?

1. **핵심 역량 집중**  
   대부분의 회사는 소프트웨어 개발이 핵심 역량이 아니다. AI가 코드를 작성해도, 회사들은 여전히 소프트웨어를 구매할 것이다.

2. **유지보수의 끝없는 여정**  
   앱을 작성하는 것은 시작일 뿐이다: 유지보수, 보안 패치, 새 기능, 표준 변경... 소프트웨어는 한 번 만들고 끝이 아니다.

3. **코드 이상의 가치**  
   소프트웨어를 판다는 것은 단순히 코드를 파는 게 아니다: 지원, 컴플라이언스, 통합, 교육... 이것이 회사들이 순수 오픈소스 대신 유료 제품을 쓰는 이유다.

#### 소프트웨어 회사에게 AI 코드 작성이 의미하는 것

소프트웨어 회사들이 **AI를 사용해 더 많은 코드를 더 빠르고 효율적으로 작성**할 것이다.  
→ **코드 작성 비용이 제로에 가까워지면, 모든 소프트웨어 회사가 무한한 코드를 작성할 수 있다.**

---

### 3. AI 경쟁의 본질: 출판사의 교훈

**유추: 인터넷이 출판사에게 가져온 변화**

- **1990년대 출판사의 착각:** 인터넷 → 전 세계가 우리 시장이다!
- **현실:** 배포 비용이 제로가 되자, **모든 출판사가 경쟁자**가 되었다.
- **결과:** 콘텐츠는 넘쳐나고, **경제력은 Google 같은 Aggregator에게 이동**

**소프트웨어 산업의 현재:**

- AI 덕분에 **코드 작성 비용이 제로에 가까워지고 있다.**
- 한 소프트웨어 회사가 무한한 코드를 작성할 수 있다면, **모든 회사가 그럴 수 있다.**
- **SaaS 시대의 종말:**
  - 지난 10년: 틈새 기능 → SaaS 앱 → IPO → "세상을 바꾸고 있다" 자축
  - 앞으로 10년: **성장이 아닌 생존의 싸움** (모든 회사가 인접 영역 공격 시작)

**기업들의 입장:**

- 기업들은 더 많은 소프트웨어를 사지 않으려 한다.
- 오히려 **토큰 비용을 마련하기 위해 소프트웨어 지출을 줄여야 한다.**

**결과:** SaaS 산업 전체의 밸류에이션 재조정은 정당하다. 다음 10년은 **파이를 키우는 게 아니라 파이를 차지하기 위한 전쟁**이다.

### 4. Agents와 Work IQ: Microsoft의 전략

Microsoft의 에이전트 전략: **Work IQ**

> "Work IQ는 Microsoft 365 하위 데이터를 기반으로 모든 조직을 위한 가장 가치 있는 상태 유지 에이전트를 만듭니다. 사람, 역할, 아티팩트, 커뮤니케이션, 기록 및 메모리에 대한 강력한 추론 기능을 조직 보안 경계 내에서 제공합니다."  
> — Satya Nadella, Microsoft CEO

**Microsoft의 강점:**

- **Active Directory = 무료 제품 중 가장 가치 있는 것**
- 개인 워커와 그들의 모든 아티팩트, 권한, 역할을 이해
- **Identity를 중심으로 에이전트를 구축하는 것은 자연스러운 선택**

**하지만 큰 문제가 있다:**

- **Identity 기반 비즈니스는 축소되고 있다.**
- 에이전트가 인간을 대체하면, **인간 ID 수가 줄어든다.**
- **좌석당 라이선스 모델** → 돈을 덜 번다.

**Microsoft가 해야 할 일:**

1. **더 많은 비즈니스 기능을 Microsoft 소프트웨어에 직접 통합** → 에이전트 능력 향상
2. **더 많은 기능 흡수** → 더 높은 가격 책정
3. **더 큰 표면적** → 다른 소프트웨어 제조사가 Microsoft 에이전트와 인터페이스하도록 강제

### 5. Microsoft의 실적 미달: 용량 할당의 딜레마

**2026년 1월 29일 실적 발표:**

- Azure 성장률이 예상보다 1%p 낮음
- **수요는 공급을 초과했지만, Microsoft가 의도적으로 용량을 다르게 할당**

**CFO Amy Hood의 설명:**

> "들어오는 공급을 Azure 수요에 맞추는 것과, M365 Copilot 및 GitHub Copilot 같은 퍼스트파티 AI 사용 확대, R&D 팀에 대한 할당을 늘려 제품 혁신을 가속화하는 것 사이에서 균형을 맞춰야 합니다."

**의미:**

- Microsoft는 **Azure 고객보다 자신의 제품(M365 Copilot, GitHub Copilot)을 우선**했다.
- CFO: "Q1-Q2에 온라인으로 들어온 GPU를 모두 Azure에 할당했다면, Azure 성장률은 40% 이상이었을 것"

**Nadella의 정당화: "포트폴리오 접근법"**

- Azure 고객을 확보하는 것도 중요하지만, M365, GitHub, Dragon Copilot 고객도 마찬가지
- 이들은 모두 **증분 비즈니스이자 TAM(Total Addressable Market)**
- Microsoft는 **한 비즈니스를 최대화하는 게 아니라, 최고의 LTV 포트폴리오를 구축**하고 싶어 함

**R&D 투자:**

- Compute는 R&D이기도 하다
- Microsoft는 **AI를 사용해 새로운 소프트웨어를 작성**하고 있다
- 이를 위해 엄청난 GPU가 필요 → Azure 공급 부족

**Ben Thompson의 평가:**

> "Microsoft가 올바른 결정을 내렸다고 생각한다."

- Microsoft가 자체 소프트웨어에서 AI를 제대로 구현하지 못하면, 경쟁자들이 곧 침입할 것
- Wall Street가 기대한 40% Azure 성장률을 놓쳤지만, 장기적으로는 올바른 선택

### 6. Token Foundries: 새로운 클라우드 경쟁 구도

**문제 1: 칩 부족의 파급 효과**

- Microsoft가 충분한 GPU가 있었다면 Wall Street 예상을 맞출 수 있었다
- 칩 부족으로 인해 **3,570억 달러의 시가총액 증발**
- **TSMC가 유일한 옵션이며, 보수적인 CapEx를 유지하는 한, 앞으로 몇 년 후에는 더 큰 문제가 발생할 것**

**문제 2: Azure 고객들은 배신감을 느낄 수 있다**

**유추: Pre-TSMC 시대의 IDM (Integrated Device Manufacturers)**

- Intel, Texas Instruments 같은 회사들은 자체 팹을 운영
- 외부 고객이 제조 공간을 계약할 수 있었지만, **팹이 자사 제품에 필요하면 용량을 빼앗길 수 있었다**
- **TSMC의 차별화:** 순수 플레이 파운드리 → 고객과 경쟁하지 않음

**현재 Azure의 상황:**

- Microsoft가 **첫 번째 우선순위**
- 그다음 OpenAI
- 그다음에야 Azure 고객들
- Amazon과 Google도 비슷한 우선순위 결정을 내릴 것

**새로운 기회: Token Foundries (순수 플레이 토큰 파운드리)**

- **Neoclouds (새로운 클라우드 제공업체)** 또는 **Oracle**
- 고객과 경쟁하지 않는 순수 플레이 토큰 파운드리의 가치 제안이 **예상보다 클 수 있다**

## 🌍 Context: 왜 지금 중요한가?

### 1. SaaS 산업 전체의 구조적 변화

- 지난 10년간 번영했던 **"틈새 기능 → SaaS 앱 → IPO"** 공식이 무너지고 있다
- AI 코드 생성으로 **진입 장벽이 낮아지고, 모든 회사가 인접 영역을 공격**할 수 있다
- **성장이 아닌 생존의 시대** → SaaS 밸류에이션 재조정 필연

### 2. 빅테크의 우선순위 전환

- Microsoft가 **Azure 고객보다 자사 제품을 우선**한다는 것은 명확한 신호
- **클라우드는 더 이상 중립적인 인프라가 아니다** → 클라우드 제공업체는 이제 소프트웨어 제조업체이기도 하다
- 이는 **독립 SaaS 회사들에게는 악몽**이다 (경쟁자가 인프라를 통제)

### 3. 에이전트 경제의 도래

- **좌석당 라이선스 모델의 종말이 가까워지고 있다**
- 에이전트가 인간을 대체하면, **Microsoft의 핵심 비즈니스 모델이 붕괴**할 수 있다
- 하지만 Microsoft는 Work IQ로 **Identity 기반 에이전트 플랫폼**을 구축 중

### 4. 칩 전쟁의 현실

- **TSMC가 병목**이다
- GPU 부족으로 Microsoft는 **3,570억 달러를 잃었다**
- 앞으로 AI 수요가 더욱 증가하면, **칩 부족은 더 큰 문제**가 될 것

## 💡 Application: 개발자로서 어떻게 적용할 것인가?

### 1. 틈새 SaaS는 죽었다, 플랫폼 확장이 살아남는다

**행동 지침:**

- 좁은 기능 하나에만 집중하는 SaaS는 더 이상 방어 가능하지 않다
- **인접 영역을 공격하고, 플랫폼화하라**
- AI를 활용해 빠르게 기능을 확장하고, 경쟁자보다 먼저 영역을 선점하라

**예시:**

- 만약 당신이 "이메일 마케팅 SaaS"를 만들고 있다면, 이제는 CRM, 고객 지원, 분석까지 확장해야 한다
- AI 코드 생성을 활용해 **6개월 만에 인접 기능을 추가**하고, 경쟁사를 압도하라

---

### 2. 소프트웨어는 죽지 않는다, 코드 이상의 가치를 제공하라

**행동 지침:**

- AI가 코드를 작성해도, **고객이 원하는 것은 코드가 아니라 제품**이다
- **지원, 컴플라이언스, 통합, 교육, 보안**에 집중하라
- 코드는 상품화되지만, **고객 경험은 차별화 요소**다

**예시:**

- 당신의 SaaS가 AI로 생성된 코드로 만들어졌더라도, **고객이 5분 안에 온보딩하고, 10초 안에 답변을 받을 수 있다면**, 그것이 진짜 가치다
- **"우리는 코드를 파는 게 아니라, 시간을 절약해주는 솔루션을 팝니다"**

---

### 3. 에이전트를 위한 소프트웨어를 만들어라

**행동 지침:**

- 인간만을 위한 UI/UX는 충분하지 않다
- **에이전트가 사용할 수 있는 API, MCP, 플러그인**을 설계하라
- 에이전트 경제에서는 **"에이전트 친화적인 소프트웨어"가 승리**한다

**예시:**

- GitHub Copilot, M365 Copilot처럼 **"소프트웨어 + 에이전트"**를 번들로 제공
- 당신의 SaaS에 **"AI 에이전트 모드"**를 추가하라 (인간 대신 에이전트가 작업을 실행)

---

### 4. 클라우드 종속성을 줄여라

**행동 지침:**

- Microsoft, Google, Amazon은 이제 **중립적인 인프라 제공업체가 아니다**
- 그들은 당신과 경쟁할 수 있고, 당신보다 자신을 우선할 것이다
- **멀티 클라우드 전략** 또는 **순수 플레이 토큰 파운드리** (Neocloud, Oracle) 고려

**예시:**

- Oracle Cloud, Coreweave, Lambda Labs 같은 **독립 클라우드**를 대안으로 고려
- **"우리는 Azure/GCP/AWS에 종속되지 않습니다"**를 차별화 포인트로 활용

---

### 5. Microsoft의 움직임을 따라가라

**행동 지침:**

- Microsoft는 **LTV 포트폴리오를 최적화**하고 있다
- 당신도 **단일 제품이 아닌 제품군**을 생각하라
- **좌석당 라이선스 → 토큰 기반 가격 책정**으로 전환을 준비하라

**예시:**

- 당신의 SaaS가 "사용자당 $10/월"이라면, **"토큰 사용량 기반 $0.01/토큰"** 모델도 고려
- 에이전트가 당신의 제품을 사용할 때, **"에이전트당 요금제"**를 추가

---

## 🔚 결론

**Microsoft는 죽지 않는다. 하지만 싸워야 한다.**

- AI는 소프트웨어를 죽이는 게 아니라, **소프트웨어 산업의 구조를 근본적으로 재편**하고 있다
- SaaS의 황금기는 끝났다. 이제는 **성장이 아닌 생존의 시대**
- Microsoft는 **Azure보다 자사 제품을 우선**하고, **인접 영역을 공격**하며, **에이전트 플랫폼을 구축**하고 있다
- 개발자로서 우리는: **플랫폼화, 코드 이상의 가치, 에이전트 친화적 설계, 클라우드 독립성, 토큰 경제 준비**를 해야 한다

**핵심 교훈:**

> "소프트웨어는 죽지 않는다. 하지만 소프트웨어 회사는 죽을 수 있다."  
> — Ben Thompson

**당신의 선택:**

1. **틈새 SaaS에 머물며 경쟁에서 밀려난다**
2. **플랫폼화하고, 에이전트를 준비하며, 새로운 시대에 적응한다**

당신은 어느 쪽을 선택할 것인가?
